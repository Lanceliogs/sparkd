# Auth Token Spec (v0.2)

## Overview

Authentication uses two layers:

1. **Static infrastructure token** (`SPARK_AUTH_TOKEN`) — loaded from `.spark.env` or
   environment variable. Required for all sparkd routes, spark-ui management routes,
   and also grants **admin** access to spark-ui browser routes.
   If not configured, auth is disabled (backwards-compatible zero-friction dev mode).

2. **Dynamic share token** — a single UUID generated by spark-ui at startup.
   Grants **live** access to spark-ui browser routes. Shared via QR code.

Both tokens are valid on `/api/*` and `/ws`. The role is determined by which token matched.

## Layer 1: SPARK_AUTH_TOKEN

### Configuration

- Env var: `SPARK_AUTH_TOKEN`
- Also loadable from `.spark.env` (same file used by all spark binaries)
- If empty or absent: auth is disabled — all routes are open

### Who uses it

| From | To | Purpose |
|------|----|---------|
| sparkctl | sparkd | All commands (healthz, shutdown, engine control) |
| sparkctl | spark-ui | Lifecycle management (healthz, shutdown) |
| spark-ui proxy | sparkd | Forwarding browser requests to the daemon |
| Browser (localhost) | spark-ui | Admin access via meta tag injection |

### Enforcement on sparkd

ALL routes require `Authorization: Bearer <SPARK_AUTH_TOKEN>` when configured.
If missing/invalid: `401 {"error": "unauthorized"}`.

### Enforcement on spark-ui (management routes)

`/healthz` and `/shutdown` require `SPARK_AUTH_TOKEN`.

### Role on browser routes

When used on `/api/*` or `/ws`, grants `admin` role (full access).

---

## Layer 2: Share Token

### Lifecycle

1. On startup, spark-ui generates one UUID v4 token
2. Printed to stdout: `spark-ui: Share token: <uuid>`
3. Env override: `SPARK_UI_TOKEN`
4. Lives in memory only — never written to disk unless user sets it in `.spark.env`
5. Rotatable via `POST /api/auth/rotate` (requires admin)

### Role on browser routes

Grants `live` role (restricted access).

---

## Browser Route Auth

### Protected routes (require any valid token)

- `/api/*` (except `/api/auth/info`)
- `/ws`

### Unprotected routes

- Static files (`GET /`, CSS, JS, assets)
- `GET /api/auth/info`

### Role determination

| Token matches | Role |
|---------------|------|
| `SPARK_AUTH_TOKEN` | admin |
| Share token | live |
| Neither | 401 unauthorized |

## Permission Levels

### Live allows:

| Route | Description |
|-------|-------------|
| `GET /api/engine/state` | Engine state |
| `POST /api/engine/start` | Start engine |
| `POST /api/engine/stop` | Stop engine |
| `POST /api/engine/blackout` | Toggle blackout |
| `POST /api/engine/midi/reconnect` | Reconnect MIDI |
| `POST /api/project/reload` (no path body) | Reload current project |
| `GET /api/scenes` | List scenes |
| `POST /api/scenes/{id}/activate` | Trigger scene |
| `POST /api/scenes/{id}/release` | Release scene |
| `GET /api/midi/status` | MIDI status |
| `GET /api/dmx/status` | DMX status |
| `/ws` | WebSocket (state, scene events) |

### Admin only:

| Route | Reason |
|-------|--------|
| `POST /api/project/reload` (with path) | Filesystem access |
| `/api/editor/*` | Project editing |
| `/api/editor/browse/*` | Filesystem browsing |
| `POST /api/auth/rotate` | Token management |
| `GET /api/auth/tokens` | Retrieve share token |

### Frontend behavior with live role:

- Hide the Editor tab
- Hide "Load Project" button
- Show only: Start, Stop, Blackout, Reload (current), scene pads

## Localhost Injection

When serving `index.html` to `127.0.0.1` (and auth is enabled):
- Inject `<meta name="spark-token" content="<SPARK_AUTH_TOKEN>">` into `<head>`
- Inject `<meta name="spark-role" content="admin">` into `<head>`

Non-localhost clients get no injection.

## Frontend Token Flow

On page load (priority order):

1. Check `<meta name="spark-token">` → store in localStorage, set role from meta
2. Check URL `?token=<value>` → store in localStorage, strip from URL, resolve role via server
3. Check `localStorage('spark-token')` → use if present
4. If none found → show "Enter access code" input

Role resolution: `GET /api/auth/role` returns `{"role": "admin"|"live"}`.

All `fetch()` calls add `Authorization: Bearer <token>`.
WebSocket connects as `ws://host/ws?token=<token>`.
On 401: clear localStorage, show access code input.

## QR Code Sharing

A "Share" button in the nav (admin only) opens a modal:
- Fetches share token from `GET /api/auth/tokens`
- Generates QR code for `http://<lan-ip>:<port>/?token=<share-token>`
- Gives live-only access (no editor)

LAN IP exposed via `GET /api/auth/info` (no auth): `{"lan_ip": "...", "port": 7601}`

LAN IP detection priority:
1. `SPARK_LAN_IFACE` env (CIDR notation, e.g. `192.168.0.0/24`) — finds local IP on that subnet
2. Auto-detect: prefers 192.168.x.x > 10.x.x.x > 172.16-31.x.x
3. Fallback: first non-loopback interface

## Token Rotation

`POST /api/auth/rotate` (admin only):
- Generates a new share token UUID
- Returns `{"share_token": "<new-uuid>"}`
- Existing live sessions become invalid (401 on next request)
- Useful as a "kick everyone off" button during a show

## Security Notes

- Static token protects sparkd from unauthorized local processes
- Share token protects against unauthorized LAN access (random devices on show WiFi)
- Localhost injection is safe (TCP handshake prevents IP spoofing of loopback)
- Not designed to protect against attackers with local machine access
- HTTPS not required for LAN-only use but could be added later
